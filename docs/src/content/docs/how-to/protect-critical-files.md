---
title: Protect Critical Files
description: Recipe for locking configuration files, CI workflows, and database migrations from unauthorized agent modifications.
---

Autonomous coding agents frequently overwrite fundamental project files—such as bumping dependencies in `package.json`, reformatting `README.md`, or hand-writing migration files—when not strictly constrained.

This guide demonstrates how to configure granular protection rules with explicit exceptions.

---

## The Recipe

Add the following rule block to your `.policyctl.yml`:

```yaml
version: 1

vars:
  ci_dir: ".github/workflows"
  db_dir: "db/migrations"

exceptions:
  # Allow Dependabot or Renovate PRs to modify package.json
  - rule: lock-config-files
    path: "package.json"
    enforce: ignore
    note: "Dependency updates approved via automated bot"

rules:
  # 1. Protect core configuration files from agent editing
  - id: lock-config-files
    description: "Core config and manifest files must not be edited by agents"
    scope: hook
    enforce: block
    message: "File {{path}} is locked. Agent modifications are not allowed."
    when:
      any:
        - { path: "package.json" }
        - { path: "pnpm-lock.yaml" }
        - { path: "tsconfig.json" }
        - { path: "README.md" }

  # 2. Protect GitHub Actions workflow definitions
  - id: lock-ci-workflows
    description: "CI/CD definitions under .github/workflows cannot be modified"
    scope: both
    enforce: block
    message: "Changes to CI workflow {{path}} denied. Human approval required."
    when:
      path: "${ci_dir}/**"

  # 3. Enforce that migrations contain generator signature
  - id: migrations-via-generator
    description: "SQL migrations must contain the generator signature banner"
    scope: ci
    enforce: block
    message: "Migration {{path}} lacks generator banner. Run make migrate instead."
    when:
      all:
        - { path: "${db_dir}/**.sql" }
      any:
        - { diff_not_contains: "! Generated by make migrate" }
```

---

## How It Works

1. **`vars` Interpolation**: Paths defined in `vars` (`${ci_dir}`, `${db_dir}`) are expanded into the matchers automatically.
2. **`scope: hook`**: The `lock-config-files` rule runs only at agent tool-call time. Humans can edit `package.json` manually with zero friction.
3. **`exceptions`**: The `exceptions` block intercepts matching paths *after* evaluation. An exception with `enforce: ignore` strips the violation entirely.

---

## Verifying the Configuration

Test the protection rule locally using `policyctl eval`:

```bash
# Verify locked file is blocked
echo '{"tool_name": "Edit", "tool_input": {"file_path": "package.json"}}' | policyctl eval --hook
```

Output:
```text
🛑 BLOCKED: lock-config-files (package.json)
Message: File package.json is locked. Agent modifications are not allowed.
```
