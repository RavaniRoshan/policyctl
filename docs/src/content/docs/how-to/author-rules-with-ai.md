title: Author Rules with AI
description: Learn how to generate deterministic YAML rules from natural language descriptions using the policyctl Cloud AI Author.
---

Instead of manually crafting regex and glob patterns, the **policyctl Cloud AI Author** converts English intents into typed, valid `.policyctl.yml` rules.

The AI Author runs on Cloudflare Workers AI using the `@cf/meta/llama-4-scout-17b-16e-instruct` model.

---

## Using the Dashboard Interface

1. Navigate to `/dashboard/policies` in your web browser.
2. Click **"Author Rule with AI"**.
3. Type your requirement in natural language:
   > *"Block agents from modifying any docker compose files or terraform configs unless the file is inside examples/"*
4. Click **Generate**.
5. The AI Author outputs the exact YAML block and an architectural explanation:

```yaml
rules:
  - id: protect-infra-and-containers
    description: "Prevent modifications to Docker and Terraform configurations outside examples"
    scope: both
    enforce: block
    message: "Infrastructure file {{path}} cannot be modified by agents."
    when:
      all:
        - diff_paths_not_glob: "examples/**"
      any:
        - { path: "docker-compose*.yml" }
        - { path: "infra/**/*.tf" }
```

6. Click **"Append to Policy"** to save it to your repository's versioned policy feed.

## Using the API Programmatically

You can also invoke the authoring endpoint directly via the control plane REST API:

```bash
curl -X POST https://policyctl-server.shivamkumar10958.workers.dev/api/ai/author \
  -H "Authorization: Bearer $POLICYCTL_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "intent": "Deny handwritten SQL migrations and require make migrate banner"
  }'
```

Response:

```json
{
  "rule": "rules:\n  - id: enforce-migration-generator\n    scope: both\n    enforce: block\n    when:\n      all:\n        - path: db/migrations/**\n      any:\n        - diff_not_contains: \"! Generated by make migrate\"\n",
  "explanation": "This rule asserts that any file added or modified in db/migrations must include the official generator banner."
}
```

## Semantic Policy Analysis (`/api/ai/analyze`)

In addition to authoring rules, you can audit an existing pull request or commit diff for policy violations that might not yet have explicit deterministic rules:

```bash
curl -X POST https://policyctl-server.shivamkumar10958.workers.dev/api/ai/analyze \
  -H "Authorization: Bearer $POLICYCTL_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "diff": "--- a/auth.js\n+++ b/auth.js\n+ const secret = \"sk-1234567890\";"
  }'
```

The endpoint returns:
- A high-level summary of the diff.
- Identified compliance risks.
- Suggested new `.policyctl.yml` rules to prevent similar issues in the future.
