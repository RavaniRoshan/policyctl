# policyctl

**Provider-agnostic policy runtime for coding agents.**

Encode procedural rules once — "migrations must be autogenerated, never handwritten", "agents must not edit README" — and enforce them in **real time inside Claude Code / Codex / Cursor** via hooks, and again as a **hard gate in CI**. One `policyctl.yml`, every agent, every repo.

Prompt files (`CLAUDE.md`, `.cursorrules`) are advisory and get violated. Vendor denylists are per-model and coarse. `policyctl` is the missing layer: a tiny local engine + generated hook adapters per provider + a git-diff CI gate.

## Install

```bash
npm install -g policyctl
# or, no install:
npx policyctl check
```

## Quickstart

```bash
policyctl init --template full     # scaffold .policyctl.yml
policyctl list                      # show your rules
policyctl gen claude               # wire hooks into .claude/settings.json (+ a pre-commit gate)
policyctl check                    # run the CI/diff gate against the current diff
```

Add the CI gate:

```yaml
# .github/workflows/policy.yml
- run: npx policyctl check
```

## How it works

A rule has three parts: `when` (matchers), `enforce` (`block` | `fail` | `warn`), and `scope` (`hook` | `ci` | `both`).

- **Hook surface** — `policyctl eval --hook` is called by each agent's pre-tool hook on every tool call. It exits `2` to block, `1` to warn, `0` to allow. Fast and offline.
- **CI surface** — `policyctl check` parses `git diff` (including untracked files) and applies the same rules to the resulting changes. This is the source of truth for what the agent actually produced, and it also covers human PRs.

`gen` writes the exact glue for each provider (native hook where supported, plus a `pre-commit` gate everywhere), so you never hand-write a per-model plugin again.

## Rules reference

| Matcher | Mode | Meaning |
| --- | --- | --- |
| `path` | hook + ci | Glob over the file the tool touches (hook) or changed files (ci) |
| `command` | hook | Regex over a shell command (e.g. the Bash tool) |
| `tool` | hook | Tool name (exact, or `/regex/`) |
| `diff_contains` | ci | Substring that **must** be present in the diff |
| `diff_not_contains` | ci | Substring that must be **absent** (e.g. a generator signature) |
| `diff_regex` | ci | Regex over the full diff text |
| `diff_paths_glob` | ci | Glob that must match ≥1 changed file |
| `diff_paths_not_glob` | ci | Glob that must match **no** changed file |

All matchers in a rule are ANDed. A `both` rule fires on the matchers relevant to whichever surface is active.

### Example: migrations only via the generator

```yaml
rules:
  - id: migrations-via-generator
    description: "DB migrations must come from `make migrate`, never handwritten."
    scope: both
    when:
      path: "db/migrations/**"
      diff_not_contains: "! Generated by make migrate -- do not edit by hand."
    enforce: block          # hook blocks the handwrite; ci fails the build if unsigned
```

## Commands

| Command | Purpose |
| --- | --- |
| `policyctl init [--template <name>]` | Scaffold `.policyctl.yml` |
| `policyctl list` | List rules and their scope |
| `policyctl check [--from <ref> --to <ref>]` | CI/diff gate (non-zero on violation) |
| `policyctl eval --hook` | Hook evaluator (reads JSON on stdin) |
| `policyctl gen <claude|codex|cursor> [--print]` | Generate provider hook glue |

## Starter templates

`default`, `migrations`, `secrets`, `readme`, `full` — run `policyctl init --template full` to start.

## Hosted control plane (commercial)

The CLI is free and local-first. The hosted control plane is what teams pay for: **one policy, enforced across every agent and repo, with an audit trail.**

```bash
policyctl login --email you@company.com          # authenticate (token saved to ~/.policyctl/config.json)
policyctl push                                   # publish this repo's policy
policyctl pull --force                           # fetch the team policy into any repo/agent
policyctl check --report                         # CI gate that also reports violations to the feed
```

- `POST /api/login` → issues a token
- `POST /api/policy` / `GET /api/policy` → sync the org policy
- `POST /api/report` / `GET /api/violations` → the violation feed (also viewable at the dashboard `/?token=...`)
- Self-host: `docker build -f packages/server/Dockerfile -t policyctl-server . && docker run -p 8787:8787 -v $PWD/data:/data policyctl-server`

Set `POLICYCTL_SERVER` to point the CLI at your instance (default: `https://policyctl.dev`).
