## Show HN (Hacker News)

**Title:** Show HN: policyctl — enforce procedural rules across Claude, Codex, and Cursor

**Body:**

I built policyctl because I kept watching my coding agents do things I'd explicitly told them not to — hand-write DB migrations, edit READMEs, commit secrets. Prompt files (`CLAUDE.md`, `.cursorrules`) are advisory and get ignored. Vendor permission denylists are per-model and coarse.

policyctl is a provider-agnostic policy runtime. You write one `.policyctl.yml` file:

```yaml
rules:
  - id: migrations-via-generator
    scope: both
    when:
      all: [{ path: 'db/migrations/**' }]
      any: [{ diff_not_contains: '! Generated by make migrate' }]
    enforce: block
```

And it fires in real time inside Claude Code / Codex / Cursor (via generated hooks) and again as a hard CI gate (via `git diff`). One policy, every agent, every repo.

It's free, MIT, and the CLI is on npm: `npm i -g @policyctl/cli`. A hosted control plane (org policy sync + violation feed) is coming in the next release.

Would love feedback — especially from staff engineers running mixed-agent stacks.

GitHub: https://github.com/RavaniRoshan/policyctl
npm: https://www.npmjs.com/package/@policyctl/cli

## Indie Hackers

**Title:** I built policyctl to stop my coding agents from acting out of line

**Body:**

If you've used Claude Code, Cursor, or Codex for real work, you've seen it: the agent hand-writes a migration you asked it to generate, edits a README you told it to leave alone, or commits a secret you thought you'd blocked.

The problem: prompt files are advisory. Permission denylists are per-model. There's no way to encode a procedural rule ("migrations must be autogenerated") and have it actually enforced.

So I built policyctl. It's a provider-agnostic policy runtime for coding agents:

- Write one `.policyctl.yml` file
- `policyctl gen claude` (or codex, or cursor) wires the hooks
- `policyctl check` gates the diff in CI
- Same policy, every agent, every repo

It's free, MIT, and the CLI is on npm. A hosted control plane (org policy sync + violation feed) is next.

I'd love feedback from anyone running mixed-agent stacks — especially staff engineers who've hit this wall.

https://github.com/RavaniRoshan/policyctl
